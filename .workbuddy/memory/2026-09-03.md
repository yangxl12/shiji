## 修复：移动端软键盘遮挡编辑页格式工具条

- 现象：笔记编辑页底部 EditorToolbar（在 `.note-edit-footer` 内，`position:fixed; bottom:0`）在手机上调起输入法后仍停在屏幕底部，被键盘盖住。
- 根因：iOS Safari 等浏览器软键盘只收缩视觉视口、不改变布局视口，fixed 底栏被键盘遮住；Android Chrome 默认 `resizes-visual`，fixed 跟随视觉视口所以看起来正常。
- 方案：
  1. `index.html` viewport 增加 `interactive-widget=resizes-content`，让 Chromium 系改为收缩布局视口（此时测量值恒为 0，不会二次偏移）。
  2. 新增 `src/hooks/useKeyboardInset.ts`：监听 visualViewport 的 resize/scroll + window resize，rAF 合并，计算 `innerHeight - (vv.offsetTop + vv.height)`；仅当差值 > 140px 且焦点在输入元素时输出（过滤地址栏抖动）；blur 早于收起动画时保持原值防抖。
  3. `NoteEditPage`：把值写入内联 CSS 变量 `--kb-inset`；CSS 里 `.note-edit-page` 用 `height: calc(100% - var(--kb-inset,0px))`、`.note-edit-footer` 用 `bottom: var(--kb-inset,0px)`。
- 踩坑：固定定位元素同时指定 `height` 与 `top/bottom` 属于过度约束，`bottom` 会被忽略 —— 原样式有 `height:100%;min-height:100%`，必须改成 `calc()` 形式，否则抬升无效。
- 后续：遗留项已补 —— `useKeyboardInset` 提升到 App 根，以 `--kb-inset` 变量下发；同步/AI 设置抽屉（`.sync-overlay`）`bottom: var(--kb-inset,0px)`、`max-height: min(85vh,100%)`。提交 `4dfd35e` 已推送。

## 解决：星辰 VPN 虚拟网卡模式下 git 无法推送 GitHub

- 背景：VPN 开「虚拟网卡(TUN)」模式时 codex 正常，但 `git push`（SSH）握手即被重置（Connection closed by 20.205.243.166），22 与 443 端口直连均失败；切「系统代理」模式 SSH 直连正常，但两种模式互斥。
- 诊断结论（干净环境实测）：
  - 系统代理模式：SSH 直连稳定 5/5；HTTPS 直连完全不通；HTTPS 走 VPN 本地代理 `127.0.0.1:7888` 稳定 3/3。
  - SSH 经 7888 隧道（connect.exe / 自写 Python CONNECT 脚本）成功率仅 20-30% —— VPN 代理通道对 SSH 流量本身有干扰，与客户端工具无关，此路不通。
- 最终方案：**git 传输协议从 SSH 改为 HTTPS + 走 7888 本地代理**（与 codex 相同的出网路径）：
  1. `git remote set-url origin https://github.com/yangxl12/shiji.git`
  2. `git config --global http.https://github.com.proxy http://127.0.0.1:7888`（仅 github.com 域名走 VPN 代理，不影响其他 git 服务）
  3. 凭据走 GCM（首次 push 弹浏览器 OAuth 授权一次）
- 关键认知：VPN 内核（XingchenCore）的本地混合代理端口 7888 与 TUN 开关无关，两种模式下都监听，是唯一稳定的出网通道。
- 注意：VPN 未运行时 7888 不监听，GitHub 推送会失败（此时开 VPN 即可）。

## 修复（续）：编辑页软键盘抬起后底栏与光标重合

- 现象：上一版（4dfd35e）只把底栏抬到键盘上方，但输入法唤起编辑时，底栏（格式栏+设置栏）仍与光标重合。
- 根因：底栏 `position:fixed; bottom:键盘高` 是悬浮覆盖层，正文滚动容器下沿在键盘顶部那一线，而 fixed 底栏正好覆盖该区域；浏览器「光标滚入可视区」只认视觉视口（键盘上沿），光标被滚到可视区底部时正好压在 fixed 底栏下。
- 方案（commit `d6e026a` 已推送）：底栏改为文档流尾元素（`position:relative; flex-shrink:0`），整页随 `--kb-inset` 收缩到键盘上方，正文滚动容器下沿止于底栏上沿 → 光标滚入可视区天然停在底栏上方，不再压住光标。另加 JS 兜底：键盘变化后用 `editor.view.coordsAtPos` 比对容器可视下沿做二次校正。
- 校验：`.app-page-edit` 带 `transform`/`will-change` 会形成 containing block，但其本身满视口，fixed 子元素定位与相对视口等价，不影响 `--kb-inset` 映射。双平台（`interactive-widget=resizes-content` 覆盖 Android、iOS 走测量）均成立。

## 修复：笔记本网页（≥768px）笔记列表出现横向滚动条

- 现象：电脑浏览器打开笔记列表（含长标题时），底部冒出横向滚动条；同时卡片宽度严重错位（一卡撑满、一卡缩成窄条）。
- 定位：用 playwright-core 直连本地 Chrome 渲染灌好数据，遍历 DOM 取 `scrollWidth - clientWidth` —— 只有 `.note-list-scroll`（笔记列表）和 `.tags-page`（标签页）有横向溢出。
- 根因：两处桌面端网格用 `grid-template-columns: repeat(2, 1fr)`，而 `1fr == minmax(auto, 1fr)`，`auto` 最小值等于网格项的 min-content。`.note-card-title` 设了 `white-space: nowrap` 但缺 `min-width: 0`，长标题把列轨撑大 → 网格总宽超出容器 → `.note-list-scroll` 上 `overflow-y:auto` 把 `overflow-x` 计算成 `auto` → 出滚动条。`.note-card-wrapper` 也无 `min-width:0`，列轨锁死后仍会因 item min-content 自己溢出。
- 方案（三处 CSS 小改，根因治理）：
  1. `NoteCard.css` `.note-card-title` 加 `min-width: 0`（让 flex 项能收缩，`text-overflow: ellipsis` 才生效；移动端也受益）。
  2. `NoteCard.css` 桌面媒体查询里 `.note-card-wrapper` 加 `min-width: 0`。
  3. `NoteListPage.css` 与 `TagsPage.css` 桌面媒体查询里 `repeat(2, 1fr)` → `repeat(2, minmax(0, 1fr))`，锁死列轨不再被内容撑大。
- 校验：1440×900 长/短标题两套数据 + 390×844 移动端，document.scrollWidth == viewport，无任何页面级横向溢出；HMR 三次更新均成功。
- 复盘思路：横滚条排查不要再用「grep 100vw」思路，本案所有元素都没有 `100vw`/负 margin，纯属 grid + flex + nowrap 三件套的 min-content 互相作用。直接跑 playwright-core 实测 `scrollWidth - clientWidth` 是最有效的取证路径（也可复用为回归测试）。

## 修复：桌面端编辑页出现两个滚动条 + 底部空白 + 缺少格式工具栏

- 现象：电脑浏览器进入笔记详情/编辑页，点击正文开始编辑后右侧出现两条滚动条；滚动到底部出现大片空白；底栏没有手机端那个格式工具条。
- 根因：
  1. `.app-page-edit` 带 `transform` 会形成 fixed 子元素的 containing block，同时它自身还写了 `overflow-y: auto`。当内部 `.note-edit-content` 内容撑高后，外层也具备了滚动条件，于是出现嵌套滚动条；滚动外层时 fixed 子元素随 containing block 一起移动，露出下面空白。
  2. `EditorToolbar.css` 用 `@media (hover: hover) and (pointer: fine)` 把工具条在桌面端 `display: none`，导致桌面缺少格式化入口。
- 方案（2 处 CSS）：
  1. `App.css`：把 `.app-page-edit` 的 `overflow-y: auto; -webkit-overflow-scrolling: touch; overscroll-behavior-y: contain` 改为 `overflow: hidden`。编辑页内部滚动由 `.note-edit-content` 统一接管，外层不再产生嵌套滚动条。
  2. `EditorToolbar.css`：删除桌面端隐藏媒体查询，让格式工具条在桌面端也显示；更新文件头注释说明「移动端与桌面端均显示」。
- 校验：用 playwright-core + 本机 Chrome 1440×900 灌长文笔记测试，修复后仅 `.note-edit-content` 一处可滚动；滚动到底部无外层空白；底栏上方出现格式工具条。提交 `cc42811` 已推送。
- 踩坑：本机沙箱 `git push` 曾因本地 `origin/main` 追踪引用 stale 报 `cannot lock ref`；执行一次 `git pull origin main --no-rebase` 刷新追踪引用后再次 push 成功（显示 `Everything up-to-date`，说明 commit 已在远程）。
