## 修复：移动端软键盘遮挡编辑页格式工具条

- 现象：笔记编辑页底部 EditorToolbar（在 `.note-edit-footer` 内，`position:fixed; bottom:0`）在手机上调起输入法后仍停在屏幕底部，被键盘盖住。
- 根因：iOS Safari 等浏览器软键盘只收缩视觉视口、不改变布局视口，fixed 底栏被键盘遮住；Android Chrome 默认 `resizes-visual`，fixed 跟随视觉视口所以看起来正常。
- 方案：
  1. `index.html` viewport 增加 `interactive-widget=resizes-content`，让 Chromium 系改为收缩布局视口（此时测量值恒为 0，不会二次偏移）。
  2. 新增 `src/hooks/useKeyboardInset.ts`：监听 visualViewport 的 resize/scroll + window resize，rAF 合并，计算 `innerHeight - (vv.offsetTop + vv.height)`；仅当差值 > 140px 且焦点在输入元素时输出（过滤地址栏抖动）；blur 早于收起动画时保持原值防抖。
  3. `NoteEditPage`：把值写入内联 CSS 变量 `--kb-inset`；CSS 里 `.note-edit-page` 用 `height: calc(100% - var(--kb-inset,0px))`、`.note-edit-footer` 用 `bottom: var(--kb-inset,0px)`。
- 踩坑：固定定位元素同时指定 `height` 与 `top/bottom` 属于过度约束，`bottom` 会被忽略 —— 原样式有 `height:100%;min-height:100%`，必须改成 `calc()` 形式，否则抬升无效。
- 后续：遗留项已补 —— `useKeyboardInset` 提升到 App 根，以 `--kb-inset` 变量下发；同步/AI 设置抽屉（`.sync-overlay`）`bottom: var(--kb-inset,0px)`、`max-height: min(85vh,100%)`。提交 `4dfd35e` 已推送。

## 解决：星辰 VPN 虚拟网卡模式下 git 无法推送 GitHub

- 背景：VPN 开「虚拟网卡(TUN)」模式时 codex 正常，但 `git push`（SSH）握手即被重置（Connection closed by 20.205.243.166），22 与 443 端口直连均失败；切「系统代理」模式 SSH 直连正常，但两种模式互斥。
- 诊断结论（干净环境实测）：
  - 系统代理模式：SSH 直连稳定 5/5；HTTPS 直连完全不通；HTTPS 走 VPN 本地代理 `127.0.0.1:7888` 稳定 3/3。
  - SSH 经 7888 隧道（connect.exe / 自写 Python CONNECT 脚本）成功率仅 20-30% —— VPN 代理通道对 SSH 流量本身有干扰，与客户端工具无关，此路不通。
- 最终方案：**git 传输协议从 SSH 改为 HTTPS + 走 7888 本地代理**（与 codex 相同的出网路径）：
  1. `git remote set-url origin https://github.com/yangxl12/shiji.git`
  2. `git config --global http.https://github.com.proxy http://127.0.0.1:7888`（仅 github.com 域名走 VPN 代理，不影响其他 git 服务）
  3. 凭据走 GCM（首次 push 弹浏览器 OAuth 授权一次）
- 关键认知：VPN 内核（XingchenCore）的本地混合代理端口 7888 与 TUN 开关无关，两种模式下都监听，是唯一稳定的出网通道。
- 注意：VPN 未运行时 7888 不监听，GitHub 推送会失败（此时开 VPN 即可）。
